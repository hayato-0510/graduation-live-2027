# 技術スタック検討メモ

作成: 2026-11-12

## 結論（推奨）: Astro + TypeScript + Reactアイランド + Motion

今年の高専祭サイト（github.com/suzuka-kosen-festa/2026-hp、Astro 7 / React 19 / Motion 12 / npm / Node 24）と同構成にする。

### 理由

1. **静的サイトで十分**: サイトの実体は告知・出演者・タイムテーブル・アクセス情報とOPアニメーション。サーバー処理もログインもないので、SSR前提のフレームワークは過剰。
2. **前例と知見がある**: 高専祭サイトが同じ構成で本番稼働済み。OPスプラッシュの作り（コンポーネント分離、sessionStorage制御、reduced-motion / 低速回線スキップ）など、設計パターンを流用できる。ただし**見た目と動きは流用しない**（世界観を被らせない方針）。
3. **学習との接続**: 中身は TypeScript + React コンポーネントなので、主催者の React/TS 学習と直結する。春平が読んで勉強する用途でも、高専祭コードと相互に参照できる。
4. **運用が軽い**: ビルド成果物は静的ファイルのみ。無料ホスティングに置けて、当日までの更新は data の JSON 編集とデプロイだけで済む。

### 対案と落とした理由

- **Next.js**: 学習中のスタックではあるが、静的告知サイトには機能過剰（ルーティング、サーバー、画像最適化の面倒に対して得るものが薄い）。学習は educanet 側で足りている。
- **素の HTML/CSS/JS**: 最速で立つが、21組超のタイムテーブルとOPを手書きで維持するのは更新に弱い。データ駆動にできないのが致命的。
- **WordPress 等CMS**: 非エンジニア編集は楽だが、世界観（アニメーション中心）と合わず、保守先も増える。

### 構成の約束事

- コンテンツは `src/data/*.json`（bands / timetable / site 情報）に寄せ、表示側はそれを読むだけにする。高専祭サイトの entries JSON と同じ流儀。
- OPアニメーションは1コンポーネントに隔離する。世界観が変わっても差し替えはそこだけ。
- アニメーションには必ず `prefers-reduced-motion` とスキップボタンを付ける（高専祭OPの作法）。
- 色・フォントはデザイントークン（CSS変数）に置き、世界観決定後に一括で差し替えられるようにする。
