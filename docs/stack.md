# 技術スタック（確定）

このサイトが何でできているかの一覧。確定済みの構成（2026-11-13）。
初めての人向けに、1つずつ「それは何か」から説明する。

## 全体像

ブラウザに表示されるファイル（HTML / CSS / JavaScript）を、ビルドという作業で生成して、Cloudflare Pages に置いている。サーバーで動くプログラムやログイン機能は無い。

生成の流れ: `src/` の中身 → Astro がビルド → 静的ファイル → Cloudflare Pages が公開

## 中身の説明

### Astro（アストロ）— フレームワーク

サイト全体を組み立てる枠組み（フレームワーク）。ページのファイル配置がそのまま URL になる（例: `src/pages/index.astro` がトップページ）。
このサイトでは、土台のレイアウトや各セクションの組み立てを担当する。表示するだけの部分は Astro 側で完結させ、動きが必要な部分だけ React に渡す（これを「React アイランド」と呼ぶ。ページの中に小さな React の島があるイメージ）。

### TypeScript（タイプスクリプト）— 言語

プログラムを書く言語の名前。JavaScript に「型」という仕組みを足したもの。
型があると、「数値が来るはずの場所に文字列が入っている」といったミスを、実行する前にチェックで見つけられる。このリポジトリの CI で回っている型チェックがそれ。

### React（リアクト）— ライブラリ

画面の部品（ボタン、カード、一覧など）を作るためのライブラリ（部品作りの道具箱）。フレームワークではない。
このサイトでは、動きのある部分だけに使う。例: トップのロゴ変形ヒーロー、タイムテーブルの絞り込み（予定）。

### Motion（モーション）— ライブラリ

アニメーションを付けるためのライブラリ。React の部品と組み合わせて使う。
スクロールに連動した動きなどを担当する。激しい点滅や自動再生はしないのがこのサイトの約束（詳しくは下の「構成の約束事」）。

### CSS とデザイントークン

CSS は見た目（色、文字の大きさ、余白、配置）を決める言語。
色やフォントのような値を直接あちこちに書かず、決めた名前の変数（CSS変数）に1か所で定義して使い回す。この値の置き場のことをデザイントークンと呼ぶ。色を変えたくなったらトークンを直すだけで全体に効く。
このサイトのトークンは `src/styles/global.css` の先頭にある。

### JSON（ジェイソン）— データの形式

バンド情報やタイムテーブルのようなデータを書くための形式。`{ "name": "r04" }` のように、項目名と値の組で書く。
コンテンツは全部 `src/data/` の JSON に置き、表示側はそれを読むだけにする。データを直せばサイトに反映されるので、表示のコードを触らずに内容だけ更新できる。

### Node.js（ノード）と npm（エヌピーエム）

Node.js は、自分の PC の中で JavaScript / TypeScript を動かすための実行環境。ビルドやチェックはこれがやる。バージョンは 24 系で固定（リポジトリ直下の `.node-version`）。
npm は、Astro や React のようなライブラリをインストールしたり、決めたコマンド（`npm run dev` など）を実行したりする道具。

### Cloudflare Pages（クラウドフレア ページズ）— ホスティング

ビルドした静的ファイルを置いて、世界中から見られるようにする場所（ホスティング）。
GitHub と連携していて、main にマージされると本番（https://graduation-live-2027.pages.dev/）が自動で更新され、作業ブランチはプレビュー用の別 URL になる。詳しい作業の流れは [docs/dev-guide.md](dev-guide.md)。

## なぜこの構成か

1. **静的サイトで十分**: サイトの実体は告知・出演者・タイムテーブル・アクセス情報とアニメーション。サーバー処理もログインもないので、サーバー前提の仕組みは過剰。
2. **前例がある**: 同じ構成のサイトが本番稼働済み。設計パターン（アニメーションを1コンポーネントに隔離する、など）は本サイトにも取り入れた。ただし**見た目と動きは寄せない**（世界観を被らせない方針）。
3. **学習との接続**: 中身は TypeScript + React なので、触りながらその勉強になる。
4. **運用が軽い**: 成果物は静的ファイルのみ。当日までの更新は JSON の編集とデプロイだけで済む。

選ばなかったもの: Next.js（高機能だがこのサイトには過剰）、素の HTML/CSS/JS（データ駆動にできず更新に弱い）、WordPress 等の CMS（アニメーション中心の世界観と合わない）。

## 構成の約束事

- コンテンツは `src/data/*.json` に寄せ、表示側はそれを読むだけにする
- アニメーションは1コンポーネントに隔離する。世界観が変わっても差し替えはそこだけ
- アニメーションには必ず `prefers-reduced-motion`（動きを減らす設定の端末では静止画にする）に対応する
- 色・フォントはデザイントークン（CSS変数）に置き、一括で差し替えられるようにする
