# 運用ルール

サイトとリポジトリを回していく上での約束。開発の手順は [workflow.md](workflow.md)、この文書は「何をどう扱うか」の方。

## 本番について

- 本番は https://graduation-live-2027.pages.dev/ （Cloudflare Pages）
- 本番は main の中身で、main は dev からの昇格 PR でのみ変わる。直接触る方法は無い
- 普段の作業は dev に合流し、dev のプレビュー（https://dev.graduation-live-2027.pages.dev/）で合体した状態を確認してから、まとめて本番へ出す
- URL はまだ告知していない。本番に出たものは「いつ見られてもおかしくない」状態にしておく

## データの正

- 出演バンドは `src/data/bands.json`、タイムテーブルは `src/data/timetable.json`、日程・会場・タイトルは `src/data/site.json` が正。ここに書いてあることがサイトに出る
- 決まっていない項目は推測で埋めない。`null`（未定）にしておくと、サイト側も「未定」と表示する
- 形式は CI のデータ検証（`npm run validate`）が守る。検証の都合で形式を変えたい時は、検証スクリプトと JSON を同じ PR で直す（段階3の作業）

## 書いてはいけないもの

- 決まっていない情報を決まったように書くこと
- このリポジトリの外の個人的な活動や案件の話（読む人に関係が無いし、見せたくないものもある）
- 他の人が閲覧できない資料やコードを「参考にできるもの」として前提にすること

## 問題が起きたら

- **マージ後に壊れた**: あわてて手で直さず、GitHub の PR ページから Revert（打ち消しの PR）を作る。CI を通して戻すので安全
- **デプロイだけ戻したい**: Cloudflare Pages の管理画面で過去のデプロイに戻せる（コードは変わらないので、その後コード側も直すこと）
- **作業中の変更がおかしくなった**: ブランチを捨てれば main は無傷。`git checkout main` で戻って、ブランチを切るところからやり直してよい

## 権限

- リポジトリは private。見られるのは招待された人だけ
- 書く権限と管理権限は別。設定や保護ルールを変えられるのは管理者だけなので、困ったら管理者に声をかける
